# sprint-1
## Реализованные эндпоинты

- `GET /events` — получить список всех событий с параметрами фильтрации:
  - `id` (Guid) - ID события;
  - `title` (string, опциональный) — поиск по названию (регистронезависимый, частичное совпадение);
  - `from` (DateTime, опциональный) — события, которые начинаются не раньше указанной даты;
  - `to` (DateTime, опциональный) — события, которые заканчиваются не позже указанной даты;
  - `page` (int, опциональный, значение по умолчанию: 1) — страница, которую необходимо вернуть;
  - `pageSize` (int, опциональный, значение по умолчанию: 10) — количество элементов на странице;
  - `totalSeats` (int) - Общее количество мест на событии;
  - `availableSeats` (int) -  Текущее количество свободных мест.

- `GET /events/{id}` — получить событие по id; если не найдено — возвращает HTTP-ответ 404.

- `POST /events` — создать событие, возвращает HTTP-ответ 201.

- `PUT /events/{id}` — обновляет событие целиком по id; если не найдено — возвращает HTTP-ответ 404.

- `DELETE /events/{id}` — удаляет событие по id; если не найдено — возвращает HTTP-ответ 404.

- `POST /events/{id}/book` — создает бронирование для переданного eventId, возвращает информацию о созданной брони:
  - если eventId не найден — возвращает HTTP-ответ 404;
  - при отсутствии мест — возвращает HTTP-ответ 409 Conflict.

- `GET /bookings/{id}` — возвращает текущее состояние брони по её идентификатору; если бронь не найдена — возвращает 404.

## Примечания
Если произойдет ошибка, вернется сообщение в унифицированном формате `ProblemDetails`.
Изначально создано одно событие с `id = 00000000-0000-0000-0000-000000000001`.

## Модели данных

### Модель Event
- `Id` — уникальный идентификатор
- `Title` — заголовок события
- `Description` — описание события
- `StartAt` — время начала события
- `EndAt` — время окончания события
- `TotalSeats` — общее количество мест на событии
- `AvailableSeats` — текущее количество свободных мест

### Модель Booking
- `Id` — уникальный идентификатор брони
- `EventId` — идентификатор события, к которому относится бронь
- `Status` — текущий статус брони:
  - `Pending` — бронь создана, ожидает обработки;
  - `Confirmed` — бронь подтверждена;
  - `Rejected` — бронь отклонена.
- `CreatedAt` — дата и время создания брони
- `ProcessedAt` — дата и время обработки брони

## Фоновая обработка бронирования (ConfirmBookingBackgroundService)

- Сервис каждые 5 секунд опрашивает хранилище на наличие бронирований в статусе `Pending`
- Для каждой необработанной брони выполняется искусственная задержка на 2 секунды, имитирующая обращение к внешней системе
- После задержки бронь переводится в статус `Confirmed`, если событие не удалено, иначе переводится в статус `Rejected`
- После смены статуса заполняется поле `ProcessedAt`

## Запуск проекта
1. Склонируйте репозиторий.
2. В терминале (в папке проекта) выполните:
   dotnet restore
   dotnet run
3. Открыть сваггер по адресу: https://localhost:7208/swagger/index.html
4. Для запуска тестов в терминале перейдите в папку с проектом (cd ...) , затем выполните:
    dotnet test ./EventServiceTests/EventServiceTests.csproj
5. Для проверки бронирования:
    Выполнить бронирование для EventID = '00000000-0000-0000-0000-000000000001 (https://localhost:7208/events/00000000-0000-0000-0000-000000000001/book);
    Получить текущее состояния для Id, возвращённого из предыдущего запроса или забарть ссылку из location предыдущего запроса.
